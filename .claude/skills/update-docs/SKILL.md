# 設計書反映チェック＋更新

直近の実装変更を分析し、設計書を更新する。

## Step 1: 変更されたファイルの特定

```bash
git diff --name-only HEAD~${0:-1}
```

`$ARGUMENTS` が数値の場合はそのコミット数分を対象。未指定なら直近 1 コミット。
未コミット変更がある場合は `git diff --name-only` も含める。

## Step 2: チェックリスト照合

変更されたファイルに基づき、以下のチェックリストを照合:

| 変更内容 | 更新対象 |
|---------|---------|
| `Assets/Scripts/` 配下の新規クラス追加 | `docs/設計書/スクリプト一覧.md` |
| `Assets/Scripts/` 配下のクラス削除・名称変更 | `docs/設計書/スクリプト一覧.md` + `docs/features/` の参照箇所 |
| MonoBehaviour クラスの追加・変更 | `docs/設計書/コンポーネント一覧.md`（責務・依存・API 欄） |
| `Assets/Scenes/` 配下の変更 | `docs/設計書/シーン一覧.md` |
| `Assets/Prefabs/` 配下の変更 | `docs/設計書/プレハブ一覧.md` |
| ScriptableObject の追加・変更 | `docs/設計書/プレハブ一覧.md` の SO アセット一覧 |
| `docs/features/yyyymmdd_*.md` に基づく実装 | 該当する機能設計書のタスクステータスを更新 |

## Step 3: 設計書の更新

該当する設計書を読み、変更内容を反映。

**改訂履歴の記入ルール:**
- フォーマット: `| 版数 | 日付 | コミット | 内容 |`
- コミットハッシュは短縮形（7文字）を使用

## Step 3.5: 機能設計書のタスクステータス更新＋完了判定

変更が `docs/features/yyyymmdd_*.md` に基づく実装の場合:

1. 実装済みタスクのステータスを ✅完了 に更新
2. 全タスク完了判定（🔵/🟡 が残っていないか確認）
3. 全タスク完了時: 関連する設計書のみ照合（全量照合ではない）
4. 移動判定:
   - ✅ と ❌ のみ → `docs/features/completed/` に移動
   - ⏸️保留 が 1 つ以上 → `docs/features/pending/` に移動

## Step 4: 同期トラッキングファイルに記録

`docs/.doc-sync.md` の同期記録テーブルに追記:

```markdown
| {コミットハッシュ} | {日付} | {同期先の設計書と版数、または「更新不要（理由）」} | ✅ |
```

設計書の更新が不要だったコミットも `更新不要（理由）` として必ず記録する。

## Step 5: 結果報告

更新した設計書名と件数のみ簡潔に報告。更新不要の場合は「更新不要」と 1 行で報告。
